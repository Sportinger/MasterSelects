# Vector-Animation.md — audit 2026-08-02

## Verified (spot checks that held)

- `.lottie`, positively identified Lottie JSON, and `.riv` imports are classified as `lottie`/`rive`; vector metadata is prepared during media import. Evidence: `src/stores/timeline/helpers/mediaTypeHelpers.ts`, `src/stores/mediaStore/helpers/importPipeline.ts`, `src/services/vectorAnimation/lottieMetadata.ts`, `src/services/vectorAnimation/riveMetadata.ts`.
- Vector clips are visual clips restricted to video tracks, and loop-enabled vector clips have an unbounded right-trim extension. Evidence: `src/stores/timeline/clip/addClipAction.ts`, `src/components/timeline/TimelineTrack.tsx`, `src/types/vectorAnimation.ts`.
- The Properties panel labels the provider tab `Lottie` or `Rive` and exposes the documented common controls, provider metadata, state-machine inputs, and Rive Data Binding controls. Evidence: `src/components/panels/properties/index.tsx`, `src/components/panels/properties/LottieTab.tsx`, and `src/components/panels/properties/lottieTab/`.
- Provider runtimes remain split behind `src/services/vectorAnimation/VectorAnimationRuntimeManager.ts`; Lottie uses `@lottiefiles/dotlottie-web` and Rive uses `@rive-app/canvas`. Evidence: `src/services/vectorAnimation/LottieRuntimeManager.ts`, `src/services/vectorAnimation/RiveRuntimeManager.ts`, `package.json`.
- Vector settings and clip types are serialized/restored, copied through clipboard/nested-composition paths, and used by export and thumbnail rendering. Evidence: `src/stores/timeline/serialization/serializableTimelineState.ts`, `src/stores/timeline/clipboardSlice.ts`, `src/stores/timeline/nestedCompositionLoader.ts`, `src/engine/export/layerBuilder/textLayers.ts`, `src/services/timeline/timelineNestedCompositionThumbnailRuntime.ts`.

## Outdated or wrong (claim → reality, with file evidence)

- “Timeline time is converted into a deterministic target frame” → this is Lottie-specific: `LottieRuntimeManager` computes and calls `player.setFrame(...)`; Rive resolves deterministic animation time and calls `player.scrub(...)`/`drawFrame()`. Evidence: `src/services/vectorAnimation/LottieRuntimeManager.ts`, `src/services/vectorAnimation/RiveRuntimeManager.ts`, `src/services/vectorAnimation/riveRuntime/rivePlaybackPlanning.ts`.
- “If a state machine is selected, `lottieState.{stateMachine}` keyframes resolve the active state” and the corresponding provider-neutral state-selection limit → explicit state override and stepped `lottieState.*` keyframes are implemented by the Lottie runtime. Rive metadata does not publish `stateMachineStates`, and `RiveRuntimeManager` only applies selected state-machine inputs. Evidence: `src/services/vectorAnimation/LottieRuntimeManager.ts`, `src/services/vectorAnimation/RiveRuntimeManager.ts`, `src/services/vectorAnimation/riveMetadata.ts`, `src/types/vectorAnimation.ts`.
- “Rive state machines use the public high-level WASM runtime” and the claimed resulting internal-progression limitation → the client code does not establish that distinction or limitation. It uses `@rive-app/canvas`, disables autoplay, applies inputs, and calls `drawFrame()`; the doc cannot substantiate the stated limitation. Evidence: `src/services/vectorAnimation/RiveRuntimeManager.ts`, `package.json`.
- “The Media panel regenerates the missing URL and image/video thumbnail automatically” → the media-store refresh action recreates the primary object URL from a retained `File`; it regenerates thumbnails only for image/video and only when `refreshFileUrls` is invoked with thumbnail refresh enabled. Project-load hydration also recreates URLs from Raw files or retained handles. Evidence: `src/stores/mediaStore/slices/fileManage/reloadActions.ts`, `src/services/project/load/loadMediaRuntimeSources.ts`.

## Noteworthy / unusual

- The Rive and Lottie controls share a component and internal tab key named `LottieTab`/`lottie`, even though the visible label is provider-specific. Evidence: `src/components/panels/properties/index.tsx`, `src/components/panels/properties/LottieTab.tsx`.
- Vector runtime canvases are now admitted through `timelineRuntimeCoordinator`; preparation can fail with `VectorRuntimeAdmissionError` under resource policy limits. This shipped behavior was absent from the doc. Evidence: `src/services/vectorAnimation/vectorRuntimeReporting.ts`, `src/services/vectorAnimation/LottieRuntimeManager.ts`, `src/services/vectorAnimation/RiveRuntimeManager.ts`.
- Rive event handling is deliberately inert apart from debug logging, and the asset-loader hook currently logs requests then returns `false`, leaving embedded assets/CDN fallback to the Rive runtime. Evidence: `src/services/vectorAnimation/RiveRuntimeManager.ts`.
