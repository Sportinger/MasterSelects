# OCR-Analysis.md - audit 2026-08-02

## Verified (spot checks that held)

- The Agent Timeline declares the separately queryable `text` channel and the `onscreen-text` event shape, including normalized/original text, confidence, language, kind, optional normalized box, provenance, keyframe time, and half-open source interval: `src/types/agentTimeline/manifest.ts`, `src/services/agentTimeline/manifest/validation.ts`.
- The local runner is dependency-injected, passes only a leased `Blob | ImageBitmap | VideoFrame` to `LocalOcrWorker`, and releases every acquired lease in `finally`: `src/services/agentTimeline/ocr/localOcrRuntimeContracts.ts`, `src/services/agentTimeline/ocr/localOcrPipeline.ts`.
- The selector uses one representative frame per shot plus caller-supplied image-hash/text-region changes, and assigns each candidate a half-open interval ending at the next candidate or shot boundary: `src/services/agentTimeline/ocr/ocrCandidateSelection.ts`.
- Normalization uses NFKC, collapses whitespace, lowercases text, and merges only adjoining candidate intervals; emitted events are `onscreen-text`: `src/services/agentTimeline/ocr/ocrNormalization.ts`.
- Quick is disabled, while Balanced and Deep require a ready engine, available language packs, a matching `text` benchmark policy, and passing real-media cold/warm evidence; the gate enforces runtime, memory, artifact-size, and warm-cache decode limits: `src/services/agentTimeline/ocr/ocrDecisionGate.ts`, `src/services/agentTimeline/benchmark/analysisBenchmarkGate.ts`.
- The cache-key helper includes source/profile/analyzer/model/languages/candidate metadata and excludes frame payloads: `src/services/agentTimeline/ocr/ocrCacheKey.ts`.

## Outdated or wrong (claim -> reality, with file evidence)

- The claim that OCR is an available Agent Timeline channel with a local worker -> only contracts, helpers, and a test-injected runner exist. No production code calls `runLocalOcrPipeline`, supplies `LocalOcrWorker`/`OcrFrameProvider`, or registers an OCR worker. Evidence: `rg` finds the runner and runtime contracts only under `src/services/agentTimeline/ocr/` and `tests/unit/agentTimelineOcr.test.ts`; `src/services/agentTimeline/jobs/currentClipAnalysisExecution.ts` has no OCR reference.
- The claims that candidate selection is deliberately bounded and has no OCR-on-every-frame path -> `maxChangeCandidatesPerShot` defaults to `Infinity`; a caller may therefore supply a change signal for every frame. The selector itself does not decode frames, but it does not enforce a global bound. Evidence: `src/services/agentTimeline/ocr/ocrCandidateSelection.ts`.
- The claim of no 160x90 OCR -> no OCR-resolution check exists. The selector never decodes, and the local pipeline accepts arbitrary frame objects; profile settings use `160 x 90` as the spatial resolution for all profiles. Evidence: `src/services/agentTimeline/ocr/ocrCandidateSelection.ts`, `src/services/agentTimeline/ocr/localOcrPipeline.ts`, `src/services/agentTimeline/profiles/analysisProfiles.ts`.
- The claim that language packages are bundled or downloaded into a local offline cache -> these are type-level states/provenance only. There is no package-cache or downloader implementation. Evidence: `src/types/agentTimeline/ocr.ts`; `rg -n "OcrLanguagePack|download-required" src` resolves to types, decision gate, and OCR tests only.
- The claim that the default state is `unavailable` or `blocked` -> the repository has no configured production OCR runtime or default availability object. Those statuses are returned only when an external caller supplies pipeline inputs. Evidence: `src/types/agentTimeline/ocr.ts`, `src/services/agentTimeline/ocr/localOcrPipeline.ts`, `src/services/agentTimeline/ocr/ocrDecisionGate.ts`.
- The cache-key claim implies an OCR cache -> `createOcrCacheKey` exists, but no cache reads or writes it. Evidence: `src/services/agentTimeline/ocr/ocrCacheKey.ts`; its only references are `src/services/agentTimeline/ocr/localOcrPipeline.ts` and `tests/unit/agentTimelineOcr.test.ts`.

## Noteworthy / unusual

- The profile estimate and candidate selector disagree: estimates allocate 0/1/3 OCR keyframes per shot for Quick/Balanced/Deep, while the selector always creates one representative keyframe per shot and is not connected to profile settings. Evidence: `src/services/agentTimeline/profiles/analysisProfiles.ts`, `src/services/agentTimeline/profiles/analysisEstimate.ts`, `src/services/agentTimeline/ocr/ocrCandidateSelection.ts`.
- Durable artifact storage, persistence, range queries, and overview tiles map OCR artifacts/events to the `text` channel, even though no producer is integrated. Evidence: `src/services/agentTimeline/storage/AgentTimelineArtifactStorage.ts`, `src/services/agentTimeline/runtime/persistence/agentTimelineRuntimePersistence.ts`, `src/services/agentTimeline/query/rangeQueryPlanning.ts`, `src/services/agentTimeline/overview/overviewTileBuilder.ts`.
- The Analysis workspace has an on-screen-text display component and OCR item type, but its adapter hard-codes `ocr: []`; current UI cards therefore cannot display OCR results. Evidence: `src/components/panels/properties/analysisWorkspace/AnalysisSceneCard.tsx`, `src/components/panels/properties/analysisWorkspace/analysisSceneViewModel.ts`, `src/components/panels/properties/analysisWorkspace/analysisWorkspaceAdapter.ts`.
