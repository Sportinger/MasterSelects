# Security.md — audit 2026-08-02

## Verified (spot checks that held)

- The dev bridge injects `__DEV_BRIDGE_TOKEN__` only for the Vite dev server and protects `POST /api/ai-tools`; `GET /api/ai-tools` remains an unauthenticated status endpoint. Evidence: `vite.config.ts:81`, `tools/devBridge/vitePlugin.ts:285-337`, `tools/devBridge/auth.ts:164-202`.
- The dev file routes exist as `/api/local-file` and `/api/local-files`, require bridge authentication, resolve real paths, reject UNC paths, and enforce allowed roots. Evidence: `tools/devBridge/localFileEndpoints.ts:11-137`, `tools/devBridge/auth.ts:94-141`.
- Native Helper defaults remain WebSocket `127.0.0.1:9876` and HTTP `127.0.0.1:9877`; HTTP AI-tool POST routes require a bearer token and `--no-auth` disables it. Evidence: `tools/native-helper/src/main.rs:41-64,142-156`, `tools/native-helper/src/server.rs:19-35`, `tools/native-helper/src/http_server.rs:28-43,116-146`.
- Browser logger redaction covers messages, structured data, error messages, and stacks; the advertised secret-pattern classes are implemented. Evidence: `src/services/security/redact.ts:16-57`, `src/services/logger.ts:231-249`, `src/services/aiTools/handlers/stats.ts:504-506`.
- Hosted chat logging is best-effort, D1-backed, user-scoped in retrieval, and exposes the two documented history endpoints. Evidence: `functions/api/ai/chat.ts:495-523,552-566`, `functions/lib/chatLog.ts:119-159,267-346`, `functions/api/ai/chat-history.ts:5-84`.
- Credit claim token hashes, six-digit website-offer redeem-code hashes, and the signed one-hour browser cookie are implemented. Evidence: `functions/lib/creditClaims.ts:4-16,111-150`, `functions/lib/websiteFreeCreditOffer.ts:103-240`, `functions/api/credits/claim.ts:59-116`.

The current Integrations UI contains only YouTube. Evidence: `src/services/youtubeCredentialManager.ts:5-29,73-94,134-157`, `src/components/common/settings/IntegrationCredentialsSettings.tsx:11-47`, `src/stores/settingsStore.ts:3-4,116-118,255-269,588-605`.

Evidence: repository-wide `rg` audit; `src/services/youtubeCredentialManager.ts:15-29` is the current credential migration.

The current chat provider configuration exposes Kie-hosted AI; the referenced `src/components/panels/AIChatPanel.tsx` also does not exist. Evidence: `src/stores/settingsStore.ts:588-605`, `src/services/flashboard/FlashBoardChatConfig.ts:3-106`; absent paths verified with `Test-Path` and `rg --files`.

- Source footer paths `src/services/security/fileAccessBroker.ts`, `src/services/security/devBridgeAuth.ts`, and `src/components/panels/AIChatPanel.tsx` -> the first two files remain but are not the server enforcement locations described; the chat-panel path is absent. Evidence: `tools/devBridge/auth.ts`, `tools/devBridge/localFileEndpoints.ts`, `tools/devBridge/vitePlugin.ts`; `Test-Path src/components/panels/AIChatPanel.tsx` returned false.

## Noteworthy / unusual

- The repository contains a separate `src/services/security/fileAccessBroker.ts`, but server-side file access is enforced by `tools/devBridge/auth.ts`; this naming overlap can mislead maintainers about the actual boundary.
- The Native Helper exposes unauthenticated `GET /startup-token` on its loopback HTTP listener and writes the same token to the system temp directory. Unix gets a best-effort `0600`; no Windows ACL is applied. Evidence: `tools/native-helper/src/http_server.rs:191-203`, `tools/native-helper/src/main.rs:160-177`.
- `chat_logs` redacts payloads before persistence, but complete hosted-chat replay/billing state is stored separately; the documentation should not imply that `chat_logs` is the sole server-side record. Evidence: `functions/api/ai/chat.ts:497-506`, `functions/lib/chatLog.ts:119-159`.
- SAM 2 is still cached in OPFS, and stem-separation models now also use OPFS; the previous document mentioned only SAM 2. Evidence: `src/services/sam2/SAM2ModelManager.ts:9-14,32-123`, `src/services/audio/stemSeparation/StemModelManager.ts:105-120,250-264`.
