# Documentation Website

MasterSelects publishes its product documentation as a regular part of the main website at `https://www.masterselects.com/docs/`. The editor's **Info > Documentation** action opens that page in a new browser tab.

## Content and navigation

- `docs/Features/*.md` remains the single source of truth for feature documentation.
- `docs-site/` renders those pages with Astro Starlight.
- The documentation home page uses the standard Starlight layout, so the Getting Started and Features navigation is visible immediately.
- Search is generated by Pagefind and is served from the same `/docs/` path.

## Build integration

The root production build runs the editor build first and then the documentation build. The documentation sync converts the feature Markdown into Starlight content, copies shared documentation assets, and writes the static result to `dist/docs/`.

The site lives under the `/docs` base, so the sync writes every page link as `/docs/features/<page>/` (hand-written Starlight pages do the same); links to the feature index (`./README.md`, such as the "Back to Index" lines) go to `/docs/getting-started/overview/`, the page the index becomes. Each picture becomes a link to its full-size file with `width`, `height` and lazy loading after the first one; node-graph figures (`docs-shot--graph`) scroll sideways on narrow screens instead of shrinking. A running `astro dev` of the same `docs-site` keeps its content cache (the sync checks the process behind `.astro/dev.json`); the build (`--build`) always starts from a clean cache.

For shared-workspace deployments, `npm run docs:build:head` can render the committed feature-documentation state without copying unrelated uncommitted documentation changes.

## Hosting and routing

Documentation ships inside the existing `masterselects` Cloudflare Pages deployment. It does not require a separate subdomain or DNS record. The Pages middleware recognizes `/docs` and `/docs/*` as valid static documentation routes while preserving the real-404 behavior for unknown application paths.

## Verification

The deployed documentation check covers:

- `/docs/`
- `/docs/getting-started/overview/`
- representative feature pages such as `/docs/features/ai-studio/`
- `/docs/_astro/*` styles and client assets
- `/docs/pagefind/pagefind.js`

The Info-menu unit test also verifies the public URL, new-tab target, safe link relation, and menu-close behavior.
