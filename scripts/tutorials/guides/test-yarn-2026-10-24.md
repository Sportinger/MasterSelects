# Test run: a fresh agent records "Yarn" (2026-10-24)

To test the handbook, a fresh Claude Code agent (`claude -p`, no earlier context) got a one-minute
part to record: episode 2, part 3, "Yarn". The brief named the start state and the scenes, gave the
voice text, and asked it to read [`agents.md`](agents.md) first. The build server and Vite were
already running, attached to Roman's Chrome in the old 1280×720 mode. Another agent read the
agent's log every two minutes and kept these notes.

## Result

- `tutorial-videos/flamer-ep2-part3-yarn.mp4`, 55.4 s, generated voice. The agent checked it itself
  with a contact sheet at the key words.
- Commits:
  - `6d64c6cfd`: product fix, a node parameter drag moves at most one step per pixel;
  - `abd608252`: the recipe, pipeline fixes and handbook pitfalls.
- 47 minutes, 188 turns, about 11.7 USD. 11 runs: 9 without voice (8 failed), 2 with voice. The
  voice was generated only once.

## What worked

- Part 2 as a template. `connect`, `cableClick` and inserting into a cable worked as they were.
- **Building with pictures:** once the agent probed each node step with a screenshot, it moved fast
  and found the Radius bug at once.
- It checked the result itself: Radius steps visible, pointer on the named rows, "Plies" 0.35 s late
  (left as it is).
- It fixed root causes in the pipeline and in MS instead of working around them in the recipe.

## What it reported but did not fix

- The node inspector opens again on every return to the Nodes tab, so "Hide node inspector" in a
  setup has no lasting effect.
- In the narrow layout, inspector values sit below their labels without sliders, not in the unified
  inspector design.

## Lessons for the plan

- **The start state costs the most.** Of 47 minutes, about 25 went into a setup of about 40 steps.
  Checkpoints ([`plan.md`](plan.md), stage 2) remove this.
- **The setup must be visible.** The bug was found only after the agent added `--setup-shots`.
  Pictures per step and before/after on failure become the default (stage 3).
- **The attached Chrome is fragile.** Emulation was lost, and Roman's real mouse crossed the window
  in every take (51–81 events). Headless 1440p (stage 1) removes both.
- **Typing is dangerous.** Any text that reaches the editor without an open field becomes shortcuts.
  A `type` step should check that the focus is in an input before it types.
- **Pixel offsets are fragile.** A `+500` panel resize hit the wrong panel. Prefer targets that do
  not depend on pixels.
- A ready helper library for probes is missing: tab, screenshot, `locate`, `click`, state.
